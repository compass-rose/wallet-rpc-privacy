## 📄 文档结构概览

### 1. 项目需求文档 (`wallet-rpc-privacy-requirements.md`)

**文档长度**: 约12000字，40+页

**核心章节**:
1. 项目概述与动机
   - 问题陈述：钱包与RPC节点通信的隐私泄露问题
   - 研究价值：实用性、学术性、社会价值
   - 差异化优势：实时测量、多维度评估、可操作

2. 目标与范围
   - 核心目标：量化隐私泄露风险、识别攻击向量、验证解决方案
   - 项目边界：包含与排除的内容

3. 核心功能（4大模块）
   - 网络流量捕获与分析
   - 隐私泄露检测与分类
   - 风险量化评估
   - 可视化仪表板

4. 技术要求
   - 后端：Python 3.10+ / FastAPI / PostgreSQL / Redis
   - 前端：React 18+ / TypeScript / D3.js / ECharts / TailwindCSS
   - 工具：mitmproxy / scapy / pytest / Docker

5. 数据模型
   - PrivacyLeakEvent（隐私泄露事件）
   - NetworkTraffic（网络通信记录）
   - RiskAssessment（风险评估结果）

6. 验证实验设计
   - 真实环境实验：3个钱包 × 5个RPC节点
   - 控制组实验：理想隐私基准 vs 最差隐私基准
   - 实验指标：信息泄露率、用户唯一性、行为模式、时序特征、空间信息

7. 交付物
   - 软件交付物：源码、部署文档、技术文档
   - 研究交付物：研究报告、演示视频、数据集

8. 成功指标
   - 量化：5000+样本、15+窃模式、3个风险评估、10+规则、4维指标
   - 质量：响应<2秒、可用性>99%、覆盖率>70%、文档完整度>90%

**关键亮点**:
- 明确的技术栈和架构设计
- 量化的成功指标和验收标准
- 详细的实验设计和评估方法
- 完整的数据模型和API规范

## ⚠️ 风险提示

### 学业风险
- **技术选型错误**: 可能导致后期重构或延期
  - 缓解：提前技术调研，征求导师意见
- **时间管理**: 10周4人团队完成所有任务非常紧张
  - 缓解：设置2-3天buffer，优先级管理

### 技术风险
- **TLS解密失败**: 钱包配置可能无法解密
  - 缓解：准备多个备选方案，提前测试
- **数据量不足**: 真实实验数据可能不够支撑ML模型
  - 缓解：多源数据收集，采样策略调整

### 团队风险
- **协作问题**: 角色分工不清或任务重叠
  - 缓解：明确职责边界，每日站会同步
- **个人表现**: 个人贡献证据包质量参差不齐
  - 缓解：每周证据包反馈，Lead统一协调
